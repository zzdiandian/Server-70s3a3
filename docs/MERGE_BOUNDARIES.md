稳定基线是 FG175；研究塔是独立 152 源候选且 `releaseAllowed=false`。二者共有文件内容不同，不能整目录覆盖，也不能直接把研究的 Batch-Service 或 Economy-State 换进 main。

## 冲突处理

先记录 PR 的 base commit 和关联文件；rebase/merge 最新 main 后逐块检查语义，禁止“全部取我的/全部取对方”。XML 冲突按 ID 合并，检查重复 ID、前置和引用；经济字段冲突检查序列化兼容与原子保存；协议冲突核对实际字节长度和字段顺序。解决后重新编译并补跑受影响回归，不能只看冲突标记消失。

## 晋升塔功能

研究者提供相对当前 main 的最小补丁、数据白名单、原版本依据、真实请求/容量/重复/重登及旧功能回归证据，明确 AI、spawn、药品完整效果、退出清理、失败/成功奖励和真人结果。集成人逐项审核后才更新稳定源码与发布清单；不能把此前“内部回放通过”直接当作六塔已完成。

## FG182世界掉落独立边界

`research/worlddrop/build.py` 显式复制稳定145源，只在研究输出修改Batch-Service元数据初始化及Floor-Drops计划末尾，并加入独立World-Drops类和两份侧表。不要覆盖stable或tower共享文件。与普通强化和疲劳草稿合并时保留各自最小差异；材料、任务、地面容量、重复、保存重登和旧物品定义必须联检。当前只适配普通单人非领主、中性100倍率的一次抽取；完整国服外层触发、队伍/活动/战争区域未完成。原表没有的物品和概率不得补造。

## FG184塔接续边界

`research/tower-integration` 显式在155源上应用10份精确共享补丁及7个固定哈希的塔类，形成162源；公共150源和历史152源塔快照都不覆盖。塔/暗黑城共有城镇门户只保留一份。14个塔任务记录按ID处理，4个训练任务继续关闭；原39/40/41、453和暗黑城门票限制保留。此次增加角色选择前临时物品清理，必须联检金币/经验/票保留和重登。普通副本死亡范围与塔当前名单分开，不能把塔UID范围套给普通副本。构建检查和原生模型不授权发布塔客户端。

FG185只对复制后的Tower-Service再加一份精确后置补丁，修结算满包后停止轮询；原7类快照和10份基线补丁不改。新增等待只在内存中，不改存档格式、原RNG/奖励计划或门票。成功/失败结算、满包字节不变、真实腾位后同一奖励入账、重复及重登需要一起验证。其余161源和13份运行数据无变化的证明可明确复用，不能声称重跑了全部旧15组或完整AI。
